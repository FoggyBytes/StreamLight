Version 3.0.0 - The "Big UI Update" (27/05/2026)
------------------------------------------

🎨 COMPLETE UI REDESIGN — flat Xbox / Steam-inspired look from the ground up.

NAVIGATION
• Removed the old sidebar and toolbar; content area is now full-width on every screen
• Bottom status bar shows contextual gamepad prompts (A / B / X / Y / LB / RB), all clickable with the mouse too — every action surfaces as both a pad shortcut and a visible button
• Gamepad glyphs swap dynamically between Xbox and PlayStation icons based on the controller currently in use (DualSense / DualShock / Xbox / generic)
• B from Settings now returns to the page that opened it (Home or the host's app grid), not always Home
• Min window size raised to 1280×720

HOME
• Host list with portrait-card tiles and a per-host coloured gradient header
• Inline "+ Add Hosts" tile + small square Refresh button next to the last host card (replaces the top action buttons)
• Per-card Options dropdown (View All Apps, Test Network, Rename, Delete, View Details, StreamTweak Streaming Mode, Wake) that does NOT dim the background
• NIC speed polled every 2 seconds — see live transitions (e.g. 2.5 Gbps → 1 Gbps when StreamTweak Streaming Mode kicks in)
• Tailscale dual-tile (requires StreamTweak 6.3.0+): after a successful pairing via LAN IP, StreamLight asks the host (via the new TAILSCALE bridge command) whether Tailscale is installed; if yes, a one-time popup offers to create a second host tile pinned to the 100.x.y.z Tailscale endpoint. The new tile coexists permanently with the LAN tile and is address-pinned (mDNS rediscovery on the LAN cannot collapse it back into the parent). Internally NvComputer gained two new persisted fields (aliasSuffix, isAddressPinned) and ComputerManager's m_KnownHosts is now keyed by storageKey() (uuid + optional #suffix) instead of plain uuid — the underlying Moonlight UUID and server certificate are shared with the parent so no second pairing is needed. The popup can be dismissed permanently per-host
• Add Host dialog redesigned with large IP TextField + D-pad navigation (Add / Cancel buttons)
• Pair dialog redesigned: huge bright-green PIN, no background dim, fully gamepad-friendly Cancel

APP GRID (per host)
• Compact one-row header: hostname · ONLINE · IP · NIC speed · resolution · FPS
• 200×267 covers with store badges (Steam / Epic / GOG / Ubisoft / Xbox / Battle.net / EA)
• Bright-green rounded border on focus / hover, tight around the cover
• Name tooltip appears INSTANTLY below the cover (no delay), positioned outside the focus frame
• Active streaming session: cover gets a thicker (5 px) PULSING green border so the running app is unmistakable
• In-cover Play / Stop overlay removed — the same actions now live in the status bar (A "Resume" / X "Stop") when the cursor is on the running app

SETTINGS
• 6 tabs (Video / Audio / Input / Decoder / Network / Session), bold uppercase labels, LB/RB cycle between them
• Pill-style segmented selectors replace the old dropdowns — D-pad Left/Right pick the value, no popup, no focus leak
• Larger fonts throughout, every option title in bold with an optional description below
• Tooltips moved inline as subtitles (instant, no hover delay); legacy tooltips reviewed, shortened, non-Windows references removed
• Scrollbar now adapts dynamically to the active tab's content height
• D-pad navigation auto-scrolls the viewport to keep the focused row visible
• Bitrate slider: hold-to-accelerate (longer hold = faster delta), redundant prefix removed, unit fixed to "Mbps", X / □ "Default" status prompt restores the recommended bitrate
• Initial focus lands on the first control of the active tab instead of requiring several D-pad presses
• New Network option "Auto-start Tailscale on launch": when enabled, StreamLight launches Tailscale (tailscale-ipn.exe) in the background at every startup so remote hosts can be reached via their 100.x.y.z Tailscale IP without keeping the Tailscale tray manually open. The toggle persists across sessions and pairs naturally with the new Tailscale dual-tile workflow on Home. Switching it ON shows a one-shot RESTART REQUIRED dialog (Yes restarts immediately, No defers to the next launch). Switching it OFF intentionally does NOT terminate the running Tailscale instance — a brief notice informs the user that Tailscale will keep running and that auto-start is disabled for future launches. The official Windows installer from https://tailscale.com/download is required; the Microsoft Store package is not supported. Auto-start is skipped silently when Tailscale is already running (e.g. started manually or pinned to Windows startup)

VISUAL IDENTITY
• Unified bright green #00E676 across the whole UI (focus cursor, TabBar underline, ONLINE badge, slider handle, accent borders, hyperlinks)
• Ambient vertical gradient background (charcoal → deep green) on every section
• DM Sans + JetBrains Mono fonts embedded
• Mouse and gamepad focus indicators are visually consistent

WINDOWS XBOX APP INTEGRATION
• Branded tile artwork in the Windows 11 Xbox app's "My apps" section: StreamLight no longer shows the default grey square when added to the user's custom library — a 1024×1024 dark-green gradient PNG with the swoosh glow is automatically placed in the tile, matching the visual quality of the curated launchers (Steam, Epic Games Store, GOG GALAXY, Ubisoft Connect, EA App, Battle.net)
• Pre-population on install: a new optional task "Add an icon to the Xbox app's 'My apps' section" (default ON, shown next to "Create a desktop icon" during setup) seeds the CustomLibraryManagement manifest entry and tile PNG directly under %LocalAppData% — when the user opens the Xbox app for the first time after installing, StreamLight already appears in "My apps" with the proper tile, no manual "+" click required. The installer step runs as the original non-elevated user via Inno Setup's runasoriginaluser flag so the manifest lands in the correct user profile and is visible to the Xbox app
• Runtime self-heal: a QFileSystemWatcher on the CustomLibraryManagement and Images folders re-applies the branded PNG within ~250 ms whenever the Xbox app rewrites the tile (e.g. user manually adds StreamLight via "+" while the app is running, or Xbox app refreshes its metadata)
• Boot-time check: at every launch StreamLight verifies the tile PNG against the embedded artwork and refreshes it if needed — covers manual additions made while StreamLight was closed (one-shot, idempotent, ~50 ms)
• Diagnostic log at %TEMP%\streamlight-xbox-tile.log records each step (registerEntry / applyIfRegistered / watcher events) for troubleshooting installer or permission issues

FIXES
• Capability gate before launch: fixes the long-standing first-launch fallback to H.264/SDR when HDR or AV1 is enabled. Previously, if the host's serverCodecModeSupport was stale in the client's cache (e.g. the host's HDR-capable display was powered off when the background poller last fetched serverinfo, or the host had just finished booting and the encoder wasn't fully initialised), the first launch attempt would silently downgrade to H.264 and SDR; only going back to the host's app grid and resuming the session restored AV1 + HDR. StreamLight now does a synchronous serverinfo refresh inside Session::initialize, right before codec/HDR negotiation reads the capability bits, so the negotiation always sees the current host state. Bounded latency: at most 2 s on cold first launch (the fast-fail timeout already used by the background poller); subsequent launches return in well under 100 ms when the host responds quickly. The gate is skipped when the user has explicitly forced H.264 SDR without YUV 4:4:4, since none of the stale-prone bits matter on that path. If the synchronous fetch fails on every reachable address (timeout, network blip), launch proceeds with the cached state — never blocks the user

UNDER THE HOOD
• Single-instance guard: launching StreamLight while it is already running no longer spawns a second process — the existing window is brought to the foreground (de-minimized, raised and activated) and the second invocation exits immediately. Uses a per-user QLocalServer named pipe ("StreamLight-SingleInstance"); CLI subcommands (stream / quit / pair / list) remain re-entrant
• Streaming engine (FFmpeg / D3D11VA / DXVA2 / libplacebo / moonlight-common-c) untouched — same protocol and decoder pipeline as 2.3.1
• ComputerModel exposes new "address" and "gpuModel" roles to QML
• SdlGamepadKeyNavigation exposes controllerType (xbox / ps / switch / generic) and simulateKey() for click-to-pad bridging
• 7 dead 2.3.1 UI files + 11 orphan SVG icons removed from the build
• Settings storage unchanged from 2.x — Qt continues to use HKCU\Software\Moonlight Game Streaming Project\Moonlight; upgrades preserve paired hosts, preferences and certificates transparently with no migration step

⚠️ REQUIRES: StreamTweak 6.3.0 or later on the host PC for the Tailscale dual-tile workflow. Earlier versions (6.1.0+) remain fully compatible but won't expose the Tailscale endpoint — StreamLight will only show the LAN tile in that case.


Version 2.3.1 - The "Live Charts Update" (25/04/2026)
------------------------------------------

🔧 IMPROVEMENTS:
• Session telemetry send interval: reduced from 10 seconds to 1 second — SESSIONDATA is now sent once per second (one sample per connection) instead of batching 10 samples every 10 seconds; StreamTweak's live session charts on the Home page now update every second as intended

⚠️ REQUIRES: StreamTweak 6.1.0 or later on the host PC for the live session charts to display correctly.

Version 2.3.0 - The "Remote Pause Update" (17/04/2026)
------------------------------------------

✨ NEW FEATURES:
• Remote session pause from host: StreamTweak's Home page now shows a Pause button when a streaming session is active; pressing it embeds a one-shot stop signal in the next STATS response; StreamLight detects the signal and terminates the session exactly as if the user had pressed Pause locally — no UI changes on the StreamLight side
• Pause signal transport: the signal is piggybacked on the existing per-second STATS polling channel as an additional "stop":1 JSON field, requiring no new TCP connection or protocol change; the field is silently ignored by older StreamLight versions

⚠️ REQUIRES: StreamTweak 6.0.0 or later on the host PC for the remote stop to work.

Version 2.2.0 - The "Hue Sync Update" (08/04/2026)
------------------------------------------

✨ NEW FEATURES:
• Philips Hue Sync integration: a new toggle in Settings automatically starts Philips Hue Sync on the client PC when a streaming session begins and closes it when the session ends; the app is launched silently in the background with no window appearing
• Smart discovery: Hue Sync is located by querying the Windows Uninstall registry (handles custom install paths and per-user Electron installations); falls back to well-known paths if the registry entry is absent
• Silent launch: uses HueSyncStarter.exe — the dedicated background launcher shipped with Hue Sync — to start the app without any visible window

Version 2.1.2 - The "Flash Fix" (04/04/2026)
------------------------------------------

🔧 IMPROVEMENTS:

Version 2.1.1 - The "Jitter Update" (28/03/2026)
------------------------------------------

🔧 IMPROVEMENTS:
• Session telemetry — jitter reporting: RTT variance (jitter) is now collected from LiGetEstimatedRttInfo and included in every SESSIONDATA batch alongside RTT; StreamTweak stores jitter_avg and jitter_max per sample and can use them in future quality analysis

Version 2.1.0 - The "Telemetry Update" (27/03/2026)
------------------------------------------

✨ NEW FEATURES:
• Session telemetry reporting: StreamLight now streams real-time client-side metrics to StreamTweak during active sessions — FPS, frame drops, RTT, decode latency, and bitrate are sampled every second and transmitted in periodic batches; StreamTweak uses this data to generate a session quality report visible in the Logs tab

⚠️ REQUIRES: StreamTweak 5.2.0 or later on the host PC for session quality reports to appear.

Version 1.2.0 - The "Host Metrics Update" (20/03/2026)
------------------------------------------

✨ NEW FEATURES:
• Host metrics in overlay: the performance overlay now includes a "Host Metrics (StreamTweak)" section showing real-time data from the host PC — GPU %, GPU encoder %, GPU temperature (°C), VRAM used / total (MB), CPU %, and network TX (Mbps); the section is automatically hidden when StreamTweak is not reachable
• HostMetricsPoller: a background Qt component that polls StreamTweak on the host every second via the TCP bridge STATS command and keeps the latest metrics available for the overlay with no impact on streaming latency
• Graceful degradation: individual metrics that StreamTweak cannot determine (e.g. GPU temperature and total VRAM on non-NVIDIA systems) are shown as N/A; if StreamTweak is not running the entire host metrics section is omitted from the overlay

⚠️ REQUIRES: StreamTweak 4.4.0 or later on the host PC for host metrics to appear in the overlay.

Version 1.0.0 - The "First Light Update" (13/03/2026)
------------------------------------------
Initial release based on Moonlight 6.1.0.

✨ NEW FEATURES:
• StreamTweak integration: right-clicking a paired host PC now exposes two additional context menu actions — requires StreamTweak installed and running on the host PC
• Show host NIC speed: queries StreamTweak on the host via TCP and displays the current Ethernet adapter speed in real time
• Set host to 1 Gbps: sends a speed-change command to StreamTweak before connecting; a 10-second countdown is displayed before the connection becomes available; if no connection is made within 30 seconds, the host automatically reverts to its original speed
• Visual theme aligned with StreamTweak's color palette for a consistent look across both apps

🔧 CHANGES FROM UPSTREAM MOONLIGHT:
• Window title changed to "StreamLight (a Moonlight fork)"
• Discord link removed — as a fork, the upstream Moonlight Discord is not the appropriate support channel
• Auto-update checker removed — to prevent prompts to update to upstream Moonlight releases
